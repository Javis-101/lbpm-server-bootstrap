# 全检查点保留与空间触发无损归档

## 策略

- 一切已经生成的id_t*.raw全部保留，包括成功、失败和中断attempt。不抽帧，不降分辨率，不把原始标签转有损图像。
- 可用空间低于10GiB启动归档，达到15GiB停止新增归档；一次只处理一个已经结束且没有写进程的attempt。
- 低于5GiB或动态预算（活跃任务剩余输出 + 一个归档及安全余量）时停止派发新任务。
- 极低空间时请求安全中断在途工作并暂停，不用写坏结果换进度。没有可压缩样本时等待扩容/迁移，不静默删除数据。
- 阈值按生产数据根所在文件系统的实际可用字节换算GiB，不是只算某个目录的大小。

## 格式与释放条件

每个attempt单独生成checkpoints.tar.zst，使用系统libzstd流式压缩，默认level3、单工作线程。不会先落盘一个同样大的未压缩tar。

归档前记录每个文件名、大小和SHA256。写入.partial后完整流式解压校验tar成员、逐文件大小和SHA256，验证帧校验和与结束，再持久化正式归档和archive_manifest。

只有全部验证通过，才释放被归档完整替代的未压缩id_t*.raw副本。checkpoint信息仍然完整、可逐字节恢复。最终训练标签和元数据不删除。原始输入/旧实验不在清理范围内。

压缩途中失败：原RAW仍在。归档提交后清理途中中断：恢复时先再验归档，然后处理剩余重复副本。归档坏了、清单多/少文件或RAW被改动时拒绝删除。

## 存储预算

一个完整检查场为2,195,456字节；40帧为87,818,240字节=83.75MiB；1200条都满40帧的检查点合计约98.14GiB，**不是100.5GiB**。尚需加输入、prepared几何、attempt副本、最终标签、失败尝试及旧实验。

不承诺6～8倍压缩；程序实际记录压缩后大小和释放空间。归档不是备份，仍需额外持久化备份/平台数据盘保护。超出容量时暂停而不是继续写满。

## 恢复单个attempt的检查点

先从dataset_index或status得到attempt_relative，例如：

```bash
bash run.sh restore --config config/rivermind.toml \
  --attempt cases/41_123/attempts/attempt_0001 \
  --dest /root/rivermind-data/restored-41_123
```

目标目录必须为空。命令校验正式归档哈希和所有成员，再安全恢复；不覆盖已有文件，不展开链接或带../的成员。恢复后的检查点可用于后处理，**不能冒充完整LBPM Restart状态**。
